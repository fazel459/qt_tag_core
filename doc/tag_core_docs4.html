۱. نمای کلی پروژه

Tag Core یک هسته مرکزی SCADA/Historian است که داده‌های صنعتی را از درایورهای مختلف دریافت، پردازش، ذخیره و از طریق API های WebSocket و REST در اختیار GUI های مستقل قرار می‌دهد.

۳. لایه API

WebSocket Server

کانال‌ها: /ws/alarms/*، /ws/tags/batch?ids=...، /ws/dashboard/{id}، /ws/system/status

پیام‌های سرور: hello, tags.snapshot, tag.update, tags.batch, alarm.event, alarm.ack, system.status, response, pong

Command Channel

عملیات‌ها: write_tag, ack_alarm, get_current, reload_drivers, start_driver, stop_driver, list_drivers, load_dashboard

{ "type":"command", "id":"req-1", "op":"write_tag", "payload":{"tag_id":1,"value":55} }
{ "type":"response", "id":"req-1", "ok":true, "data":{...} }

Alarm Sync

{ "type":"alarm.ack", "alarm_id":123, "tag_id":5, "user_name":"operator", "ts":"..." }

ack از REST یا WS → broadcast به کانال‌های alarms/all + analog + digital. رویدادهای raised/cleared از قبل via TagBus sync بودند.

REST API (خلاصه)

گروهEndpoint ها
TagsGET/POST /api/v1/tags، GET/PUT/DEL /{id}، /{id}/current، /{id}/history
AlarmsGET /api/v1/alarms، POST /{id}/ack
DashboardsGET/POST /api/v1/dashboards، /{id}، /{id}/content، /{id}/resources
ReportsGET /api/v1/reports/tag-history|alarms|daily-summary
UsersPOST /api/v1/auth/login|logout، GET /auth/me، CRUD /users

Driver Management API (CRUD)

MethodEndpointتوضیح
GET/api/v1/driversلیست درایورها
POST/api/v1/driversساخت درایور (+ start خودکار اگر enabled)
PUT/api/v1/drivers/{id}ویرایش (+ restart خودکار اگر فعال)
DEL/api/v1/drivers/{id}حذف (اگر تگ داشته باشد → 409)

نمونه Request

{ "name":"Modbus TCP Test", "type":"modbus_tcp",
  "connection_config":{"host":"127.0.0.1","port":502},
  "polling_interval_ms":1000, "enabled":false }

رفتار runtime

عملرفتار
POST با enabled:trueدرایور همان لحظه start می‌شود
PUT روی درایور فعالstop + start خودکار (restart با کانفیگ جدید)
DELETE با تگ❌ 409 — اول تگ‌ها را حذف/جابه‌جا کن
DELETE موفقدرایور stop و سپس از DB حذف می‌شود

اعتبارسنجی: type باید یکی از simulator/modbus_tcp/modbus_rtu/mqtt/opc_ua باشد و connection_config یک JSON object معتبر.

User Management

کاربر پیش‌فرض: admin / admin123. رمز با salt + SHA-256. نقش‌ها: admin (همه)، operator (همه جز /users)، viewer (فقط GET). ارسال token: Authorization: Bearer <token>

Dashboard API (File-based)

انواع: simple (JSON)، qml، html. فایل‌ها در dashboards/{id}/. خروجی content همیشه string است.

Report Generation

فرمت: json یا csv (با BOM برای Excel). interval: raw, 1 minute, 5 minutes, 1 hour, 1 day

Authentication

پیش‌فرض غیرفعال (حالت development). فعال‌سازی: UPDATE system_settings SET value_text='true' WHERE key='api.auth.enabled';

۴. راهنمای تست

🎛 تست Driver CRUD (PowerShell)
# ساخت
$body = @{ name="Modbus TCP Test"; type="modbus_tcp";
  connection_config=@{host="127.0.0.1"; port=502}; enabled=$false } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri "http://127.0.0.1:8082/api/v1/drivers" -Method Post -Body $body -ContentType "application/json"

# فعال‌سازی (restart خودکار)
Invoke-RestMethod -Uri "http://127.0.0.1:8082/api/v1/drivers/7" -Method Put `
  -Body (@{enabled=$true} | ConvertTo-Json) -ContentType "application/json"

# حذف
Invoke-RestMethod -Uri "http://127.0.0.1:8082/api/v1/drivers/7" -Method Delete
