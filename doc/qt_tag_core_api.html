🏗 ۱. معماری

Client (Flutter / Web / HMI)
       ↕
REST API (HttpServer) + WebSocket Server
       ↕
Core: TagBus → RuleEngine → DeadbandFilter → Writers
       ↕
DriverManager → ITagDriver (Modbus/OPC UA/MQTT/Simulator)
       ↕
Storage: DbManager → BatchHistorianWriter → CurrentStateWriter → ArchiveManager

درایورها اکنون CRUD کامل دارند. ایجاد → استارت خودکار، ویرایش → ری‌استارت خودکار، حذف → توقف + بررسی وابستگی تگ‌ها.
GET/api/v1/driversBearer

لیست درایورها

{

    {
      "driver_id": 1,
      "name": "PLC-01",
      "type": "modbus_tcp",

      "enabled": true,
      "connection_config": { "host": "192.168.1.10", "port": 502 }
    }
  ],
  "count": 3
}
POST/api/v1/driversadminجدید

ایجاد درایور + استارت خودکار

Body:

{
  "name": "PLC-02",                    // اجباری
  "type": "modbus_tcp",               // اجباری
  "connection_config": {
    "host": "192.168.1.20",
    "port": 502,
    "unit_id": 1
  },
  "polling_interval_ms": 500,         // حداقل 100ms

Response (201):

{ "created": true, "driver_id": 4, "started": true }

PUT/api/v1/drivers/{id}adminجدید

به‌روزرسانی + ری‌استارت خودکار

اگر درایور در حال اجرا باشد، متوقف و با کانفیگ جدید ری‌استارت می‌شود.

Body (فیلدهای اختیاری):

Response (200):

{ "updated": true, "driver_id": 4, "restarted": true }
کددلیل
400type نامعتبر / connection_config نامعتبر
404درایور یافت نشد
500خطای دیتابیس
DELETE/api/v1/drivers/{id}adminجدید

حذف درایور + توقف

⚠️ محدودیت
اگر تگ‌هایی به این درایور متصل باشند، خطای 409 برمی‌گردد. ابتدا تگ‌ها را حذف یا منتقل کنید.

Response (200):

{ "deleted": true, "driver_id": 4 }

Response (409):

{ "error": "Cannot delete driver: 5 tag(s) reference it. Delete or move tags first." }
کددلیل
404درایور یافت نشد
409تگ‌هایی به درایور متصل هستند
500خطای دیتابیس

🔀 ۱۲.۱ URL Routing (هنگام اتصال)

هنگام اتصال WebSocket، می‌توانید در URL مسیر subscribe را مشخص کنید:

URLعملکرد
ws://host/ws/alarms/analogاشتراک آلارم‌های آنالوگ
ws://host/ws/alarms/digitalاشتراک آلارم‌های دیجیتال
ws://host/ws/alarms/allاشتراک همه آلارم‌ها
ws://host/ws/system/statusاشتراک وضعیت سیستم
ws://host/ws/tags/batch?ids=1,2,3اشتراک تگ‌ها در حالت batch
ws://host/ws/dashboard/{id}?ids=1,2,3اشتراک داشبورد + تگ‌هایش
💡
پس از اتصال، سرور پیام hello و سپس tags.snapshot (در صورت subscribe تگ) ارسال می‌کند.

🎮 ۱۲.۲ Control Messages (Client → Server)

ping

client → server 
{ "op": "ping" }
server → client 
{ "type": "pong", "ts": "..." }

subscribe / unsubscribe

client → server 
{
  "op": "subscribe",
  "channel": ["alarms/all"],
  "tags": [1, 2, 3],
  "dashboard": ["main"],
  "delivery": "batch"
}
📋 کانال‌های مجاز
alarms/analog ، alarms/digital ، alarms/all ، system/status
📸 Snapshot خودکار
هنگام subscribe تگ‌ها، snapshot فعلی آن‌ها بلافاصله ارسال می‌شود.

options (تغییر حالت دریافت)

client → server 
{ "op": "options", "delivery": "batch" }
  • event — هر تغییر بلافاصله ارسال می‌شود (پیش‌فرض)
  • batch — تغییرات تجمیع و هر batch_interval_ms (پیش‌فرض 100ms) ارسال می‌شوند

get_snapshot

client → server 
{ "op": "get_snapshot", "tags": [1, 2] }

اگر tags ذکر نشود، snapshot همه تگ‌های subscribed ارسال می‌شود.

اتصال WebSocket با subscribe اولیه

const ws = new WebSocket('ws://localhost:8080/ws/tags/batch?ids=1,2,3');

ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  switch (msg.type) {
    case 'hello': console.log('Connected:', msg.session); break;
    case 'tags.batch': msg.updates.forEach(u => console.log(`Tag ${u.tag_id}: ${u.value}`)); break;
    case 'tags.snapshot': console.log('Snapshot:', msg.tags); break;
    case 'alarm.event': console.log('ALARM:', msg.severity, msg.category); break;
    case 'response': console.log(msg.ok ? 'OK:' : 'ERR:', msg); break;
  }
};

ارسال Command از طریق WebSocket

ws.send(JSON.stringify({
